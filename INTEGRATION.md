# Platform Integration Guide

This guide explains how to integrate external systems (e.g. `paisawin.online`) with our tracking platform via Postback API.

## Postback API Overview

A **Postback API** is a server-to-server webhook that confirms a successful conversion (like a user registration). Your platform must make an HTTP request to our server when a tracked event occurs.

### Endpoint

```http
POST https://yourdomain.com/api/postback
Content-Type: application/json
```

### JSON Payload

The request body must be a JSON object containing the following fields:

- `code` (string, required): The unique tracking code generated by the publisher or traffic user. This is typically captured from the URL parameter when they land on your site.
- `uid` (string, required): The unique ID of the user on *your* system (e.g., the User ID or Phone Number from the game). This ensures duplicate conversions are ignored.
- `type` (string, optional): The type of link being credited — `"publisher"` or `"traffic"`. If omitted, the platform resolves it automatically from the `code`.
- `secret` (string, required): The secret postback key to authenticate your server. Default development secret is `your-postback-secret-key-for-dev` (or the value set in GlobalConfig).

### GET Alternative

If your panel can only fire a pixel/GET postback, the same endpoint accepts query parameters:

```http
GET https://yourdomain.com/api/postback?code=A1B2C3D4E5&uid=user_987654321&type=traffic&secret=your-postback-secret-key-for-dev
```

Aliases are accepted for convenience: `code` (`ref`, `ref_code`, `subid`, `sub_id`), `uid` (`user_id`, `userid`, `external_user_id`) and `secret` (`key`).

### Example Request

```json
{
  "code": "A1B2C3D4E5",
  "uid": "user_987654321",
  "type": "traffic",
  "secret": "your-postback-secret-key-for-dev"
}
```

### Example cURL

```bash
curl -X POST https://yourdomain.com/api/postback \
  -H "Content-Type: application/json" \
  -d '{
    "code": "A1B2C3D4E5",
    "uid": "user_987654321",
    "type": "traffic",
    "secret": "your-postback-secret-key-for-dev"
  }'
```

### Expected Responses

**Success (200 OK):**
```json
{
  "success": true,
  "credited": 3.00
}
```

**Ignored / Duplicate / Invalid (200 OK with success: false):**
The API intentionally returns `200 OK` even for logical errors to prevent external systems from endlessly retrying.

```json
{
  "success": false,
  "reason": "duplicate" 
}
```
*Note: Possible error reasons include `Invalid secret`, `link not found`, `link is inactive`, and `duplicate`.*

### Troubleshooting: conversions not counting

Every rejected postback is logged server-side as `[postback not credited] <reason>`. Check the reason first:

- `Invalid secret` — the `postback_secret` row in GlobalConfig does not match what your panel sends. Set it under Admin → Settings. Until that row exists the API accepts the development defaults only.
- `link not found` — the `code` you send is not the tracking code. Send back the `ref` value we append to the landing page URL (also stored in the `ref_code` / `traffic_ref` cookie).
- `duplicate` — this `uid` was already credited. Publisher conversions are deduplicated per publisher, traffic conversions per link, so the same test user is credited only once.
- `link is inactive` — the traffic link has been disabled.
